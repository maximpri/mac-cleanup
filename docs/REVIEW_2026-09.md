# Product review — September 2026

A review of Diskray's goal, its use of Apple Foundation Models, and its
terminal interface, measured against [Mole](https://github.com/tw93/Mole)
(V1.56, about 68k stars, the most popular open-source Mac cleaner). It records
what changed in this pass and what should come next.

## 1. Goal

**Stated goal:** "An X-ray for your Mac's disk. Understand before you delete."
Measure where space went, explain each large item with evidence, and only then
act through one reviewed, verified plan.

**Assessment.** The goal is sound and well differentiated. Mole competes on
breadth and speed ("CleanMyMac + AppCleaner + DaisyDisk + iStat Menus in one
binary"). Diskray can't win on breadth without giving up its safety model, and
it shouldn't try. Mole's own issue tracker points to the opening: an SSD write
loop after deleting open cache files, a corrupted System Settings after
`optimize`, and most deletes being permanent. Diskray's evidence, in-use
checks, typed confirmations, and before/after verification answer exactly
those failures.

**Risks to the goal:**

- **Scope drift.** `PRODUCT_REVIEW.md` and `IMPLEMENTATION_PLAN.md` describe a
  unified "Mac care" product covering CPU, memory, and processes. The shipped
  identity (README, name, tagline) is disk-first. The process and memory
  features are useful evidence for disk decisions, but a second product front
  (performance tuning) would compete with Mole's `status`/`optimize` on its
  home ground. Recommendation: keep performance as *evidence* ("this cache is
  in use by X"), not as a destination.
- **First-run value depends on AI readiness.** The AI is the headline
  differentiator, but it was gated behind an English (United States)
  requirement that nothing in the code enforced (fixed in this pass, see §2).
- **Coverage perception.** "Covers fewer locations on purpose" is honest, but
  users compare totals. Report-only finders (`artifacts`, and now
  `installers`) add visible value without widening what can be deleted
  automatically.

## 2. Apple Foundation Models

### What is right

- **Architecture.** A Swift helper speaks newline-delimited JSON (protocol v3).
  The model calls read-only Rust tools through `Tool` bridging, sees folders
  and processes only as opaque handles (`n2`, `p1`), and must cite numbered
  evidence. Rust validates every report and writes all displayed prose from
  the tool results. This is the strongest design choice in the project: a
  3B-parameter on-device model is used for *choosing and citing*, which it
  does well, not for *stating facts*, which it does poorly.
- **API use.** Availability and unavailable reasons, `DynamicGenerationSchema`
  with `anyOf` choices constrained to Rust-issued IDs, greedy sampling for ID
  selection, exact `tokenCount(for:)` preflight on 26.4+, a runtime
  `contextSize` instead of a hard-coded 4096, and a mapped case for every
  `GenerationError`.
- **Budgets.** At most six tools per investigation family, so their
  definitions fit the context; 6 calls in 2 minutes interactively; 560-byte
  outputs.

### Problems found

| # | Problem | Where | Status |
| --- | --- | --- | --- |
| 1 | "English (US) required" was shown for **every** unavailable reason, including ineligible hardware and Apple Intelligence being off. Nothing in the code enforced it, and the readiness record shows the actual failure was missing model assets, not language. | `presentation.rs` Ask bar and F3 page | **Fixed.** A blocker appears only when the Mac language is unsupported or differs from Siri's (`ModelDiagnostics::language_blocker`); tags compare case- and separator-insensitively. |
| 2 | The model was told its tool budget once and never updated. | `agent.rs` tool replies | **Fixed.** Every result ends with "N tool calls left". |
| 3 | Greedy sampling can repeat an identical call; each repeat re-ran the collector and spent budget. | `agent.rs::handle_call` | **Fixed.** Repeats get "Already checked as E3" without spending budget; repeats are bounded; process samples are exempt. |
| 4 | `rate_limited` / `concurrent_requests` fell straight to the non-AI path. | `ai.rs::request_once` | **Fixed.** One cancellable retry after 1.5 s. |
| 5 | Triage instructions never stated the ranking rule. | `AIHelper.swift` triage | **Fixed** (prompt text only). |
| 6 | Result summaries had no length bound, and their text is displayed. | `AIHelper.swift` resultSummary | **Fixed** (prompt text only). |
| 7 | One helper process per request: `prewarm()` is called immediately before `respond`, so it cannot overlap anything. | `AIHelper.swift` agent op | Open — see roadmap. |
| 8 | Context use during a run is estimated at 3 bytes/token although the helper has the exact tokenizer. | `agent.rs` `CONTEXT_BYTES` | Open — see roadmap. |
| 9 | Prompts are serialized JSON; plain labelled lines cost 20–30% fewer tokens with a small model. | `agent.rs` prompt packet, `ai.rs` triage | Open — needs live evaluation before changing. |
| 10 | Helper stderr is discarded, so framework diagnostics are lost. | `ai.rs::HelperProcess::spawn` | Open. |

Swift changes in this pass are limited to prompt text because the helper
cannot be compiled off macOS. Live inference is still unverified on the
development Mac (see [AI_READINESS_2026-09-24.md](AI_READINESS_2026-09-24.md));
`python3 scripts/check_ai_helper.py --live` remains the release gate.

## 3. Terminal interface

### Strengths

- Two persistent panels with the explanation beside the list. Mole's tools are
  separate full-screen programs.
- Measured progress ("Scanned 3.2M files in 41 s"), never an invented percentage.
- A reconciled space balance with no invented total — nothing in Mole matches it.
- A command palette (`:`), contextual clickable footer, mouse support, reduced
  motion, `NO_COLOR`, and usable layouts down to 60 × 16.

### Problems found and fixed in this pass

- **Rows had no visual proportion.** Every analyzer users compare against
  (Mole's `analyze`, ncdu, DaisyDisk) shows bars. Rows now carry a
  status-colored proportional bar (eighth-block resolution) and the item's
  share of used space, right-aligned into a scannable column. They are
  omitted when the status text needs the room.
- **Paths were cut through the middle of folder names**
  (`~/peek/co…pp/target/debug/app`). `truncate_path` now drops whole leading
  folders and keeps the item name: `~/…/target/debug/app`, then `…/debug/app`.
- **The Ask bar took 4 of 16 rows** on small terminals even when AI was
  unavailable. Under 24 rows it now takes one line, with a clickable
  `F3 AI unavailable` badge, and expands when you start typing.
- **The footer listed "browse" twice** (`Enter` and `e`). It now shows
  `/ ask`, making AI discoverable from the main screen.

### Still open

- Row status labels such as "Other" and "Temporary" for folders inside
  projects are vague. `artifacts` already knows `target` and `node_modules`,
  so those rows should say "Rust build output · rebuild with cargo build".
- On a nearly empty volume the capacity bar reads as blank. Label the used
  fraction numerically beside the bar.
- `--no-color` is a top-level flag that clap rejects with subcommands
  (`diskray --no-color why`). `NO_COLOR=1` works; the flag should be global.

## 4. Diskray vs Mole

| Area | Mole | Diskray after this pass | Gap |
| --- | --- | --- | --- |
| Cache/log/temp cleanup | Very broad, fast, mostly permanent | Narrower rule packs, typed confirmation, in-use and whitelist checks, logged, verified | Breadth — grow rule packs (community TOML) |
| Disk analyzer | Bars, top 30, delete to Trash | Balance with hidden space, evidence panel, heatmap, bars, reviewed Trash | — |
| Build artifacts | `mo purge` (selectable, deletes) | `diskray artifacts` (report only) | Add reviewed Trash plan for artifacts |
| Installers | `mo installer` | `diskray installers` + MCP `old_installers`, notes installed apps and mounted images | Surface as findings in the TUI |
| App uninstaller | `mo uninstall` with leftovers | — | **Biggest gap** (roadmap 1) |
| Live system status | `mo status` dashboard, health score | Memory pressure and process evidence inside findings | Intentionally not a destination |
| Optimize (DNS flush, rebuild caches) | `mo optimize` | — | Out of scope; caused Mole's worst incident |
| AI | None | On-device, tool-using, cited, cannot act | Diskray's lead — make it reliably available |
| Coding agents | — | Read-only MCP (14 tools), proposals reviewed by the user | Diskray's lead |
| History | Operations log | Per-action outcomes, growth since last scan, recurring items | — |

## 5. Roadmap, in priority order

1. **Reviewed app uninstaller.** Match leftovers only by exact bundle ID
   (`~/Library/Containers/<id>`, `Group Containers`, `Preferences/<id>.plist`,
   `Application Support/<name>` only when its `Info.plist` or receipts tie it
   to the bundle). Show every path and its evidence in the right panel, put
   it in the plan as review-only data, and move it to Trash — never permanently delete.
   This closes the one gap users cite most, with Diskray's safety model intact.
2. **Long-lived AI helper.** Start the helper when Ask is focused or `i` is
   pressed, create the session, call `prewarm(promptPrefix:)`, then send the
   question. Keep it alive for the workspace session. This removes process
   start-up and framework load from every question.
3. **Exact context accounting.** Count tool outputs with `tokenCount(for:)` in
   `Bridge.call` on 26.4+ and return the context-budget reply from the helper;
   drop the Rust byte estimate where exact counts exist.
4. **Report finders as findings.** Show `installers` and `artifacts` results
   in the storage list with their own status ("Installer · app installed",
   "Rust build output · untouched 90 days") and a reviewed Move to Trash.
5. **Community rule packs.** Coverage grows safely through reviewed TOML packs;
   publish a contribution guide with a pack template and fixture tests.
6. **Prompt compaction**, measured with `scripts/eval_agent.py` on a Mac whose
   model is ready: labelled lines instead of JSON, triage subjects trimmed to
   the fields the ranking uses.

## 6. Validation of this pass

Checks run on Linux (the helper and native Trash cannot run here):

- `cargo fmt --check`, `cargo clippy --all-targets --all-features -D warnings`,
  and `cargo doc` with `-D warnings`: clean.
- `cargo test --all-targets`: all new tests pass. The same 13 pre-existing
  tests fail as before, because they depend on macOS `lsof` behavior.
- `scripts/smoke_tui.py` and `scripts/check_mcp.py`: pass against a build with
  the macOS guard disabled for local testing only (not committed).
- Not verified: live Apple FM inference, and the Swift prompt edits (text only,
  not compiled).
